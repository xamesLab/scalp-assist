# Контур Charts: руководство для агента

## Назначение

`/app/charts` — приватная страница ручного наблюдения за perpetual-контрактами.
Она показывает свечные графики в сетке из двух столбцов. Активных графиков может
быть от 0 до 10; новое браузерное хранилище начинается с BTC и ETH.

Это отдельный контур. Не связывать его типы и каталог с
`internal/arbitrage/charts.go`: арбитражные графики требуют один контракт сразу
на трёх биржах и сравнивают линии цен, а Charts использует одну OHLC-серию.

## Выбор источника

Каноническая идентичность — `BASE:MULTIPLIER`, например `BTC:1` или
`PEPE:1000`.

1. Предпочитать Binance.
2. Если Binance-контракта нет, использовать Bybit.
3. Внутри одной биржи предпочитать USDT, затем USDC.
4. Учитывать только активные linear perpetual-контракты.
5. Сохранять фактический exchange symbol только в серверном каталоге, а не в
   `localStorage`.

## Backend

Основная реализация: `internal/charts/service.go`.

- `GET /api/charts/instruments` возвращает актуальный каталог.
- `WS /api/charts/stream` принимает команды `subscribe`/`unsubscribe`.
- Один браузерный сокет обслуживает до десяти `slot_id`.
- Одинаковые `(instrument_id, interval)` между клиентами используют один
  upstream WebSocket.
- При последнем unsubscribe upstream отменяется.
- История ограничена 300 свечами.
- Поддерживаемые интервалы: `5m`, `1h`.
- Bybit wire-интервалы: `5`, `60`; Binance: `5m`, `1h`.

`domain.Kline` содержит `Open`, `High`, `Low`, `Close`, `OpenTime`, `Closed`.
Корреляция и старые арбитражные графики по-прежнему используют `Close`.

## Frontend и localStorage

Компонент страницы: `web/src/ChartsPage.jsx`.
Общая модель состояния: `web/src/chartGridStorage.js`.

Ключ:

```text
scalpAssist.chartGrid.v1
```

Формат:

```json
{
  "version": 1,
  "charts": [
    {
      "id": "stable-slot-id",
      "instrument": {"base": "BTC", "multiplier": 1},
      "interval": "1h"
    }
  ]
}
```

Инварианты:

- порядок массива равен порядку карточек;
- `id` относится к слоту, поэтому одна монета может встречаться несколько раз;
- максимум 10 слотов;
- пустой массив допустим;
- дефолт BTC/ETH применяется только при первом запуске или повреждённой версии;
- неизвестный interval заменяется на `1h`;
- запись всегда делается после повторного чтения актуального состояния.

Между вкладками используется событие браузера `storage`. В текущем документе
отправляется `scalp-assist:charts-changed`. Страница Charts показывает
уведомление об изменении в другой вкладке и применяет его кнопкой
`Refresh layout`.

## Set charts

На Screener и Prop screen кнопка `Set charts` включает колонку чекбоксов.

- checkbox checked, если инструмент присутствует хотя бы в одном слоте;
- checked добавляет один слот с `1h`;
- unchecked удаляет все слоты этого инструмента;
- при десяти слотах добавление отклоняется;
- клик по checkbox Screener не раскрывает строку;
- Prop screen использует фактический `contract_multiplier`.

Нажатие на заглушку страницы Charts всегда добавляет ещё один BTC. Дубли BTC
разрешены. После десятого графика заглушка скрывается. Кнопка × в карточке
удаляет только этот слот; снятие checkbox в таблице удаляет все слоты монеты.

## Обязательные проверки

```powershell
go test ./...
go build ./cmd/screener
Set-Location web
npm.cmd test
npm.cmd run build
```

Отдельно проверять Binance priority и Bybit fallback, OHLC REST/WS parsing,
wire-интервалы, общий upstream, правильный `slot_id`, стабильность дефолтных
slot IDs, дубли, удаление всех совпадений, лимит 10 и отсутствие утечек подписок.
