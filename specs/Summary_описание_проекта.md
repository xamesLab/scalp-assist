# Scalp Assist: описание проекта

**Версия:** 3.1
**Дата:** 29.07.2026

## Идея

Scalp Assist — личный информационный веб-сервис для анализа фьючерсного рынка.
Он круглосуточно собирает только публичные данные бирж и объединяет несколько
независимых рабочих контуров под одной авторизацией.

Сейчас реализованы три контура:

1. **Скринер** отбирает кандидатов для скальпинга по правилам методички:
   оборот, движение и диапазон дня, корреляция с BTC, инплей и prop list.
2. **Prop screen** показывает все доступные на Binance или Bybit монеты из prop
   list, их изменение и оборот за 24 часа. Binance является приоритетным
   источником метрик, Bybit используется при отсутствии Binance-контракта.
3. **Арбитраж** показывает межбиржевые расхождения цен бессрочных USDT-фьючерсов
   Binance, Bybit и OKX: направление сделки, gross/net spread, доступную ёмкость
   первого уровня стакана и влияние funding.

Сервис ничего не покупает и не продаёт, не использует API-ключи аккаунтов и не
выдаёт команд «войти в сделку». Это статистика для последующей ручной оценки.

## Страницы

`/` остаётся публичным лендингом. `/auth` содержит форму входа. После успешного
входа пользователь попадает на общий приватный dashboard `/app`, где видит
короткое состояние каждого контура и переходит в нужный раздел.

Приватные маршруты:

- `/app` — общая сводка;
- `/app/screener` — текущий топ скринера;
- `/app/screener/history` — история скринера;
- `/app/screener/settings` — правила отбора и prop list;
- `/app/screener/wiki` — русскоязычная справка по Top, метрикам, score и
  рабочему процессу;
- `/app/prop-screen` — список доступных prop-монет и их 24h-метрики;
- `/app/prop-screen/wiki` — справка по фильтрам, столбцам и использованию
  корреляции с BTC;
- `/app/arbitrage` — список текущих межбиржевых возможностей и статистика;
- `/app/arbitrage/settings` — зарезервированная вкладка настроек арбитража;
- `/app/arbitrage/wiki` — русскоязычная справка по работе с List, столбцам,
  формулам и ограничениям данных.

При истечении сессии приватные страницы переводят на `/auth`. После logout
выполняется принудительный переход на лендинг `/`.

## Общая архитектура

Приложение остаётся одним Go-процессом и одной React SPA. Контуры разделены на
уровне доменной логики, сервисов, API и таблиц БД, но переиспользуют сетевые
клиенты Binance/Bybit, нормализацию инструментов и TTL-кэши market data.

```text
Binance ─┐
Bybit ───┼─ exchange adapters + shared TTL cache ─┬─ screener scheduler
OKX ─────┘                                        ├─ prop-screen service
                                                 └─ arbitrage service
                                                        │
                                              SQLite + REST API
                                                        │
                                                   React SPA
```

Так скринер и арбитраж не запрашивают повторно один и тот же каталог или ticker
payload, если данные ещё свежие. Параллельные обращения к одному cache key
объединяются в один фактический HTTP-запрос.

## Контур скринера

- Binance и Bybit, быстрый цикл по умолчанию раз в 15 минут.
- Медленный пересчёт недельной корреляции с BTC раз в 2 часа.
- Binance — приоритетный источник ценовых метрик, Bybit дополняет оборот и
  покрывает собственные листинги.
- Результат — ранжированный top-N, история снапшотов и статистика.
- Prop list можно редактировать вручную и импортировать из TXT. Блок свёрнут по
  умолчанию, чтобы длинный список не занимал страницу.

## Контур арбитража

Первая версия сравнивает только линейные бессрочные USDT-контракты Binance,
Bybit и OKX с одинаковой нормализованной идентичностью
`base + quote + multiplier + kind`.

Для каждой пары бирж рассматриваются оба направления:

```text
gross_bps = (sell_bid / buy_ask - 1) * 10000
net_bps   = gross_bps - buy_fee_bps - sell_fee_bps
capacity  = min(buy_ask * buy_ask_size, sell_bid * sell_bid_size)
```

Перед показом применяются проверки:

- обе котировки положительные и достаточно свежие;
- временной перекос между биржами не превышает лимит;
- контракт Trading и совпадает множитель;
- gross spread находится в допустимом диапазоне;
- net spread и ёмкость не ниже настроенных порогов.

Funding переводится к значению в час с учётом интервала. Для экономии запросов
детальная funding-информация догружается только для верхней части списка.
Результаты обновляются по умолчанию раз в 10 секунд, а история записывается не
чаще раза в минуту и хранится 30 дней.

Текущая версия использует REST и только первый уровень BBO. Поэтому spread и
capacity являются индикатором для анализа, а не гарантией исполнимой прибыли.

## Контур prop-screen

Контур читает существующую prop list и раз в минуту сопоставляет её с активными
линейными perpetual-контрактами Binance и Bybit. Внутри биржи USDT имеет
приоритет над USDC. Для метрик используется Binance, а при отсутствии валидного
Binance-контракта — Bybit. Медленный цикл рассчитывает корреляцию часовых
доходностей каждой строки с BTC за 7 дней.

Последний результат хранится в памяти; отдельная история и таблицы БД не
создаются. Каталоги и 24h ticker payload переиспользуют общие TTL-кэши. Страница
показывает источник каждой строки, состояние обеих бирж, поиск и сортировку.

## Контур Charts

Приватная страница `/app/charts` показывает до десяти одиночных свечных
графиков в сетке из двух столбцов. Источник выбирается в порядке Binance →
Bybit, поддерживаются таймфреймы 1 час и 5 минут. История загружается REST,
текущая свеча обновляется через общий серверный WebSocket hub.

Порядок, монеты и интервалы являются настройкой браузера и хранятся в
`scalpAssist.chartGrid.v1`. Screener и Prop screen изменяют тот же список через
режим `Set charts`; другие вкладки получают событие `storage`.

## Безопасность и эксплуатация

- Только публичные market endpoints, без торговых ключей.
- HTTPS в production, JWT в HttpOnly-cookie, bcrypt-хэш пароля.
- SQLite в WAL-режиме; миграции применяются автоматически.
- Один статический Go-бинарник с встроенным frontend.
- Недоступность одной биржи отображается как деградация; арбитраж продолжает
  работать, пока доступны минимум две биржи.
